# Microservice LLM Plan

================================================================================
# 1. Vision & Architecture Overview
================================================================================
The objective of this architecture is to bridge the Rust (Tauri) backend to a dedicated Python microservice running FastAPI, LangChain, and LangGraph. The Python service acts as a stateless, high-throughput LLM router supporting both remote cloud providers (OpenAI, Anthropic, etc.) and local OpenAI-compatible inference backends (vLLM, llama.cpp/llama-server).

### Security, Network Boundaries & Encryption Model
- **Local Loopback / IPC (Rust <-> Python)**:
  - Runs entirely within OS kernel memory via loopback (`127.0.0.1`) or local domain sockets/pipes.
  - No TLS/HTTPS encryption overhead is required since traffic never enters a physical network wire.
  - Authenticated via an ephemeral random session secret (`X-Fixture-Internal-Token`) generated by Rust at boot, blocking unauthorized local processes from querying the engine.
- **Egress to Cloud APIs (Python -> OpenAI / Anthropic)**:
  - Fully encrypted using TLS 1.3 / HTTPS (port 443), managed transparently by `httpx` inside `langchain-openai`.
  - Credentials remain strictly ephemeral in request headers and are never written to disk in Python.
- **External Platform Integration (Slack, Discord, Jira)**:
  - Slack & Discord: Outbound persistent WebSocket connections initiated by the desktop app (Slack Socket Mode, Discord Gateway).
  - Jira: Outbound HTTPS REST polling utilizing Tokio async background tasks with user-configurable intervals.
  - No inbound network ports or internet-facing webhooks are exposed on the user's desktop.

# 2. Functional & Non-Functional Requirements
================================================================================

### Functional Requirements
1. **Dynamic Provider & Endpoint Configuration**:
   - Support arbitrary OpenAI-compatible base URLs (e.g. `http://localhost:8000/v1` for vLLM or local network endpoints like `http://192.168.1.100:8080/v1`).
   - Support standard cloud endpoints (e.g. `https://api.openai.com/v1`).
   - Support IBM Watsonx.ai (`watsonx`) endpoints (e.g. `https://us-south.ml.cloud.ibm.com`) with IBM IAM token exchange, project ID (`projectId`), and Granite/Llama models.
   - Support IBM Watsonx Orchestrate (`watsonx_orchestrate`) for digital skill and agent orchestration (`https://api.orchestrate.watsonx.ibm.com`) targeting specific assistant or skill IDs.
   - **Dual-Key Priority Toggle & Failover Architecture**:
   - The system supports two primary API key choices configured in frontend Tauri: Option A (OpenAI gateway key) and Option B (Watsonx.ai IBM Cloud API key).
   - The user toggles which provider serves as the active priority key, with the remaining provider serving as the automatic standby fallback.
   - Upon invocation, the microservice attempts the query using the prioritized provider.
   - If the prioritized provider encounters network failure, rate limiting (HTTP 429), or service degradation (HTTP 5xx), the microservice automatically fails over to the standby fallback key and logs a sanitized warning.
      - Response metadata records whether failover occurred and which provider fulfilled the query.
   - Allow configuration of model names and temperature settings.
2. **Secure Credential Lifecycle**:
   - Zero plaintext storage of API tokens in `.env` files or JSON settings on disk.
   - Credentials stored in OS Keyring with service identifier `fixture_llm_service` (`ibm_cloud_api_key`, `fallback_api_key`, `bob_orchestrate_token`).
   - Python microservice treats credentials as ephemeral, in-memory request-scoped tokens.
3. **Local Loopback Isolation & LAN Attack Mitigation**:
   - **Strict Loopback Binding**: Microservice binds strictly to `127.0.0.1` (never `0.0.0.0`), preventing any other device on the LAN/Wi-Fi from reaching the service.
   - **Ephemeral Shared Session Secret (Internal Token Authentication)**:
     - Upon launching the Python process, Rust generates a cryptographically secure random session token (UUID v4 / 256-bit random).
     - Rust passes this token to Python via environment variables or stdin at startup.
     - Every request from Rust to Python must include `X-Fixture-Internal-Token: <secret>`.
     - Any unauthorized local process querying `http://127.0.0.1:8765` is rejected with `401 Unauthorized`.
   - **Strict CORS Protection**:
     - CORS restricted to Tauri's internal origin schemes (`tauri://localhost` or `http://tauri.localhost`).
     - Wildcard `*` origins and arbitrary external browser requests forbidden to block Cross-Site Scripting (XSS) and DNS rebinding.
4. **Data Redaction & Sanitization Layer**:
   - Outbound prompt sanitization preventing unintended transmission of secret tokens, API keys (regex matching patterns like `sk-[a-zA-Z0-9]{20,}`), and private file paths.
   - Logging redaction: all debug logs scrub `Authorization` headers, sensitive tokens, and payload secrets before writing to stdout or disk.
5. **Configurable Tokio Smart Polling for Jira**:
   - Adaptive smart polling engine in Rust implemented as an asynchronous `tokio::time::interval` background task.
   - Delta updates querying Atlassian REST APIs using time-bounded JQL (`assignee = currentUser() AND updated >= -Xm`).
   - Dynamically adjustable polling frequency (e.g., 15s, 30s, 60s, 120s, or manual sync only) driven by user preferences configured in the `SettingsMenu` modal.
   - Dynamic pause/resume triggered when the app is minimized or backgrounded to minimize unnecessary API calls and CPU overhead.
6. **LangChain & LangGraph Orchestration**:
   - Use `langchain_openai.ChatOpenAI` dynamically parameterized with request-specific `base_url` and `api_key`.
   - State graph management with `langgraph` for chat history, tools, and multi-step reasoning.

### Non-Functional Requirements
- **Convention Alignment**: Adhere to `AGENTS.md` guidelines (PascalCase types/files, camelCase runtime values, CAPITALIZED constants, section partitions, no inline prose comments).
- **Security & Isolation**: Process separation ensures that LLM dependency crashes or native CUDA errors in vLLM do not crash the Tauri desktop window.
- **Resource Footprint**: Near-zero CPU and memory consumption during idle state across polling loops and local microservice processes.
- **Portability**: Native support across Windows, macOS, and Linux without platform-specific hardcoding.

# 3. Target File Structure & Affected Files
================================================================================

### Affected & New Files
- `planning/W_MicroserviceLLM.md`: Active architecture and execution plan.
- `services/Security.py`: Middleware for session token verification, origin validation, and data redaction filters.
- `services/Server.py`: FastAPI application entry point, security middleware wiring, and route definitions.
- `services/ChatRouter.py`: LangChain dynamic client builder, multi-provider routing (OpenAI, Watsonx.ai, Orchestrate), and dual-key failover.
- `services/Models.py`: Pydantic request and response contracts.
- `src-tauri/src/ProcessManager.rs`: Spawns the Python microservice sidecar, manages lifetime, and injects session secret.
- `src-tauri/src/SecretStore.rs`: Keyring integration for reading and writing tokens to the OS secret store.
- `src-tauri/src/JiraPoller.rs`: Tokio smart polling worker with configurable intervals and channel-based update triggers.
- `src-tauri/src/Commands.rs`: Tauri invoke commands exposed to TypeScript (LLM chat dispatch with dual-key priority & loopback POST, credential management, poller interval updates).
- `src-tauri/src/lib.rs`: Registration of commands and initialization.
- `src/components/SettingsMenu.ts`: Frontend settings modal component supporting polling interval controls and provider configurations.

# 4. Detailed Implementation Steps
================================================================================

### Phase 1: Security & Python Microservice Specification (`services/`)
1. **Implement `services/Security.py`**:
   - `InternalTokenMiddleware`: inspects incoming `X-Fixture-Internal-Token` against server boot secret.
   - `RedactionFilter`: regex patterns to scrub API keys (`sk-...`, Bearer tokens) and file paths from logs and outbound payloads.
2. **Define Pydantic Models (`services/Models.py`)**:
   - `ChatRequest`: contains `prompt`, `messages`, `provider` (priority provider), `apiKey` (priority key), `modelName`, `baseUrl`, `projectId`, `spaceId`, `fallbackProvider`, `fallbackApiKey`, `fallbackModelName`, `fallbackBaseUrl`, `fallbackProjectId`, `enableFallback`, `temperature`, `maxTokens`.
   - `ChatResponse`: contains `reply`, `modelUsed`, `providerUsed`, `fallbackTriggered`, `fallbackReason`, `tokensPrompt`, `tokensCompletion`.
3. **Implement Dynamic Chat Builder (`services/ChatRouter.py`)**:
   - Function to dynamically create `ChatOpenAI(base_url=req.baseUrl, api_key=extracted_key, model=req.modelName)`.
   - Dedicated client routing for `watsonx` (IAM OAuth token exchange + IBM foundation models inference) and `watsonx_orchestrate` (digital employee assistant and skill run dispatching).
   - LangGraph basic state graph execution with memory / context state.
4. **Implement FastAPI App (`services/Server.py`)**:
   - Strict binding configuration to `127.0.0.1`.
   - CORS middleware restricted to `tauri://localhost` and Tauri dev origins.
   - Wire `InternalTokenMiddleware` and redaction handlers.
   - Endpoints: `GET /health` (readiness probe), `GET /api/models` (dynamic model catalog), `POST /api/chat` (inference dispatch).

### Phase 2: Rust Credential, Security & Client Integration (`src-tauri/`)
1. **Implement `ProcessManager.rs`**:
   - Generates ephemeral random session token on startup.
   - Spawns Python process with the secret injected via environment or stdin.
   - Graceful termination on application shutdown.
2. **Implement `SecretStore.rs`**:
   - `setSecret(account: &str, secret: &str) -> Result<(), String>` using `keyring::Entry`.
   - `getSecret(account: &str) -> Result<Option<String>, String>`.
   - `deleteSecret(account: &str) -> Result<(), String>`.
   - `clearAllSecrets() -> Result<usize, String>`.
3. **Implement `JiraPoller.rs` with Configurable Tokio Intervals**:
   - Asynchronous Tokio worker managing dynamic polling intervals via `tokio::sync::watch` channel.
   - Dispatches outbound delta JQL search requests and emits Tauri events to the frontend.
   - Provides runtime reconfiguration method to adjust polling frequency on the fly.
4. **Expose Tauri Commands (`Commands.rs` & `lib.rs`)**:
   - `save_llm_secret`: persists tokens (OpenAI and Watsonx) into OS Keyring via `SecretStore`.
   - `execute_chat`: reads credentials from `SecretStore`, evaluates user's active priority toggle, injects `X-Fixture-Internal-Token`, and issues the authenticated loopback HTTP POST directly via `reqwest` to Python's `/api/chat`.
   - `update_jira_poll_interval`: updates the Tokio poller interval from frontend user selection.
   - `get_available_models`: fetches available model catalog from Python microservice for dropdown selection.

### Phase 3: Frontend Settings Integration (`src/`)
1. **Implement / Update `SettingsMenu.ts`**:
   - Polling interval configuration input (dropdown for 15s, 30s, 60s, 120s, or Manual).
   - LLM Provider switcher (Cloud vs. Local vLLM/llama.cpp URL) and secure token input.
   - Dispatches settings changes via Tauri `invoke` commands.

### Phase 4: Verification & Integration Testing
1. Test rejection of unauthenticated local requests (verify `401 Unauthorized` without `X-Fixture-Internal-Token`).
2. Test rejection of unauthorized external / browser origins (CORS check).
3. Test redaction filters with simulated prompt containing dummy API keys.
4. Verify Tokio Jira poller adapts dynamically when updated from the settings modal without restarting the process.
5. Validate round-trip Tauri invoke command execution from frontend.
